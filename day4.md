## Задача 15 — `ordersByUser(orders)`

**Что сделать:** сгруппировать заказы по `userId`. Ключ — `userId`, значение — массив заказов этого пользователя.

**Обязательный метод:** `reduce`

**Правила:**
- Порядок заказов внутри группы = порядку во входном массиве
- Не мутировать входные данные
- Пустой массив → `{}`

**Критерии "готово":**
1. `ordersByUser(orders)` → `{ "1": [o1, o5], "2": [o2, o3], "3": [o4] }`
2. Порядок внутри каждой группы сохранён
3. `ordersByUser([])` → `{}`
4. Это по сути `groupBy(orders, "userId")` — если ученик заметит и заменит, отлично
5. Один проход

**Крайние случаи:**
- `ordersByUser([])` → `{}`
- Один заказ → `{ "1": [order] }`
- Все заказы одного пользователя → один ключ, все заказы в нём

**Типовые ошибки:**
1. `acc[userId] = [order]` — перезаписывает вместо добавления
2. Не замечает, что это `groupBy` — дублирует код
3. Забыл `initialValue: {}`

**Мини-проверка:**

```js
const result = ordersByUser(orders);

result["1"];
// → [
//   { id: "o1", userId: 1, status: "created", amount: 100, currency: "USD" },
//   { id: "o5", userId: 1, status: "created", amount: 90, currency: "USD" }
// ]

result["2"];
// → [
//   { id: "o2", userId: 2, status: "confirmed", amount: 250, currency: "USD" },
//   { id: "o3", userId: 2, status: "cancelled", amount: 80, currency: "EUR" }
// ]

result["3"];
// → [{ id: "o4", userId: 3, status: "confirmed", amount: 120, currency: "EUR" }]

ordersByUser([]);
// → {}
```

## Задача 16 — `buildReport(users, orders)`

**Что сделать:** собрать финальный отчёт, **переиспользуя уже написанные функции**. Не дублировать логику — вызывать готовые функции.

**Обязательный подход:** композиция — вызов ранее написанных функций

**Правила:**
- Тело `buildReport` должно быть коротким — максимум 10-15 строк
- Каждое поле вычисляется вызовом существующей функции
- Никакого `reduce`/`for` внутри `buildReport` — вся логика уже в утилитах
- Не мутировать входные данные

**Структура результата:**

```js
{
  usersCountByRole:    { admin: 2, user: 2, moderator: 1 },
  usersByCity:         { Moscow: [Alice, David, Eva], Perm: [Bob, Charlie] },
  ordersCountByStatus: { created: 2, confirmed: 2, cancelled: 1 },
  ordersSumByCurrency: { USD: 440, EUR: 200 },
  ordersByUserId:      { "1": [o1, o5], "2": [o2, o3], "3": [o4] }
}
```

**Критерии "готово":**
1. Результат содержит все 5 полей с правильными данными
2. Каждое поле вычислено через вызов существующей функции (не через inline reduce/for)
3. Тело функции — не больше 10-15 строк
4. `buildReport([], [])` возвращает объект с пустыми значениями (пустые объекты)
5. Входные `users` и `orders` не мутированы
6. Функция читается как «декларативное описание отчёта»

**Крайние случаи:**
- `buildReport([], [])` → все значения `{}`
- `buildReport(users, [])` → поля по users заполнены, по orders — `{}`
- `buildReport([], orders)` → поля по orders заполнены, по users — `{}`

**Типовые ошибки:**
1. Дублирует логику вместо вызова существующих функций — весь смысл задачи в композиции
2. Забывает одно из полей
3. Путает `countBy` и `groupBy` — в `usersByCity` нужна группировка (объекты), не подсчёт (числа)
4. Не тестирует на пустых данных

**Мини-проверка:**

```js
const report = buildReport(users, orders);

report.usersCountByRole;
// → { admin: 2, user: 2, moderator: 1 }

report.usersByCity;
// → { Moscow: [{Alice}, {David}, {Eva}], Perm: [{Bob}, {Charlie}] }

report.ordersCountByStatus;
// → { created: 2, confirmed: 2, cancelled: 1 }

report.ordersSumByCurrency;
// → { USD: 440, EUR: 200 }

report.ordersByUserId;
// → { "1": [o1, o5], "2": [o2, o3], "3": [o4] }

// Пустые данные
const emptyReport = buildReport([], []);
emptyReport.usersCountByRole;    // → {}
emptyReport.ordersSumByCurrency; // → {}
```

**Пример идеального решения (не подглядывать до реализации):**

```js
function buildReport(users, orders) {
  return {
    usersCountByRole:    countBy(users, "role"),
    usersByCity:         groupBy(users, "city"),
    ordersCountByStatus: countBy(orders, "status"),
    ordersSumByCurrency: sumOrdersByCurrency(orders),
    ordersByUserId:      groupBy(orders, "userId"),
  };
}
```

Обрати внимание: тело — 7 строк. Вся логика — в утилитах. `buildReport` только собирает результат.

## Задача 17 — Рефакторинг: убрать дублирование

**Что сделать:** пройтись по всем функциям за 4 дня и заменить специализированные версии вызовами универсальных.

**Обязательный подход:** переиспользование

**Замены:**

| Специализированная | Заменить на | Пример |
|---|---|---|
| `countByRole(users)` | `countBy(users, "role")` | тело: 1 строка |
| `groupByAge(users)` | `groupBy(users, "age")` | тело: 1 строка |
| `countOrdersByStatus(orders)` | `countBy(orders, "status")` | тело: 1 строка |
| `ordersByUser(orders)` | `groupBy(orders, "userId")` | тело: 1 строка |

**Критерии "готово":**
1. Каждая специализированная функция — обёртка в 1 строку над универсальной
2. Все предыдущие тесты по-прежнему проходят
3. Универсальные функции (`countBy`, `groupBy`, `indexBy`, `pluck`) — единственные, содержащие логику
4. Ученик понимает принцип DRY (Don't Repeat Yourself) на практике

**Критические вопросы для ученика:**
- `sumOrdersByCurrency` — можно ли заменить на `countBy`? Нет! `countBy` считает **количество**, а `sumOrdersByCurrency` считает **сумму**. Это другая операция. Оставить как есть.
- `getAdults`, `findFirstByRole`, `hasAnyRole`, `allFromCity`, `sortByAge` — эти функции **не дублируют** универсальные, у них своя логика. Оставить как есть.

- [ ] **Все функции чистые** — ни одна не мутирует входные данные

- [ ] **some/every** возвращают boolean
- [ ] **every([])** → true — ученик объясняет почему
- [ ] **sort** работает на копии — оригинал не изменён
- [ ] **Нет дублирования** — специализированные функции переиспользуют универсальные
- [ ] **buildReport** — тело не содержит reduce/for, только вызовы функций
- [ ] **Пустые массивы** — все функции корректно обрабатывают `[]`
- [ ] **pluck** — длина результата = длина входа (undefined, не пропуск)

### Задания на самопроверку:

**Вопрос 1:** Назови 3 функции, которые стали обёрткой в 1 строку после рефакторинга. Почему это хорошо?

**Вопрос 2:** Почему `sumOrdersByCurrency` нельзя заменить на `countBy`? В чём принципиальная разница?

> Ответ: `countBy` считает **количество** вхождений ключа (инкрементирует на 1). `sumOrdersByCurrency` считает **сумму** по полю `amount`. Разная операция аккумуляции.

**Вопрос 3:** Если завтра появится новый набор данных (например, `products`), какие из твоих функций можно переиспользовать без изменений?

> Ожидаемый ответ: `countBy`, `groupBy`, `indexBy`, `pluck` — они универсальные, работают с любым массивом объектов.

**Бонус-вопрос:** Напиши функцию `sumBy(array, groupKey, sumKey)` — универсальное суммирование по группам. Тогда `sumOrdersByCurrency` тоже станет обёрткой.

```js
// Подсказка:
function sumBy(array, groupKey, sumKey) {
  return array.reduce((acc, item) => {
    const key = item[groupKey];
    acc[key] = (acc[key] || 0) + item[sumKey];
    return acc;
  }, {});
}

const sumOrdersByCurrency = (orders) => sumBy(orders, "currency", "amount");
```
